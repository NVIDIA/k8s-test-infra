OPTION B: NVIDIA DRA Driver (requires DRA-enabled cluster)

  Cluster prerequisites (KIND):
    kind create cluster --config tests/e2e/kind-dra-config.yaml

  The kubelet plugin's node affinity requires a GPU-presence label. NFD derives
  one from the feature file this chart writes; without NFD, set it by hand:

    kubectl label node --all nvidia.com/gpu.present=true

  Install:
    helm repo add nvidia https://helm.ngc.nvidia.com/nvidia
    helm repo update

    helm install nvidia-dra-driver nvidia/dra-driver-nvidia-gpu \
      --version 0.5.0 \
      --namespace nvidia \
      --create-namespace \
      --set nvidiaDriverRoot=/var/lib/nvml-mock/driver \
      --set gpuResourcesEnabledOverride=true \
{{- $multiNode := eq (include "nvml-mock.multiNodeNVLink" .) "true" }}
{{- /* The NRI plugin hands the IMEX daemon nvidia-imex.real. */}}
{{- $computeDomains := and $multiNode .Values.nri.enabled }}
{{- if $computeDomains }}
      --set resources.computeDomains.enabled=true \
      --set altProcDevices=/var/lib/nvml-mock/imex/proc-devices \
{{- else }}
      --set resources.computeDomains.enabled=false \
{{- end }}
      --wait --timeout 180s
{{- if $computeDomains }}

  ComputeDomains: the {{ .Values.gpu.profile }} profile's NVLink spans nodes, so
  the node agent stages IMEX and the driver runs ComputeDomains with its
  upstream images. IMEX comes from imex.payload.image or, while the
  IMEXDownload feature gate is on, a download from NVIDIA. The driver's
  kubelet plugin looks for IMEX only when it starts, so install the driver
  once every node has it:

    kubectl -n {{ .Release.Namespace }} exec <node pod> -- \
      test -f /var/lib/nvml-mock/driver/usr/bin/nvidia-imex.real

  and restart the plugin on a node that gets IMEX later.
{{- else if $multiNode }}

  ComputeDomains are off: they need nri.enabled=true, since the NRI plugin
  hands the driver's IMEX daemon the real nvidia-imex.
{{- end }}

  Verify ResourceSlices:

    kubectl get resourceslices -o json | \
      jq '[.items[].spec.devices // [] | length] | add // 0'

OPTION C: GPU Operator

  The operator's driver and container-toolkit operands are replaced by
  nvml-mock, so both are disabled and CDI carries the devices instead.
  The overlay below carries that, plus the driver root the device plugin,
  GFD and dcgm-exporter each need in their environment.
{{- if not (.Values.nodeAgent.containerRuntime | default dict).enabled }}
  Cluster prerequisites: nodeAgent.containerRuntime is off, so each node needs
  CDI enabled in containerd and the nvidia runtime handler registered.
{{- end }}
  Walkthrough:
    https://nvidia.github.io/k8s-test-infra/guides/gpu-operator/
  In a checkout of this repository: docs/guides/with-gpu-operator/

  Install:
    helm repo add nvidia https://helm.ngc.nvidia.com/nvidia
    helm repo update

    helm install gpu-operator nvidia/gpu-operator \
      --namespace gpu-operator --create-namespace \
      -f https://raw.githubusercontent.com/NVIDIA/k8s-test-infra/main/tests/e2e/gpu-operator-values.yaml \
      --wait --timeout 600s

  From a checkout, the local path tests/e2e/gpu-operator-values.yaml works too.

  Verify the operands are running and GPUs are allocatable. The operands do
  not tolerate the control-plane taint, so check every node, not just one:

    kubectl -n gpu-operator get pods
    kubectl get nodes -o 'custom-columns=NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu'
